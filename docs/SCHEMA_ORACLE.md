# Schéma Oracle (étape 35)

Équivalent DDL des 10 modèles Mongoose de `backend/src/models/` pour Oracle XE 21c
(service `XEPDB1`). **Le code applicatif reste sur MongoDB** : ce schéma est posé à
part, aucun modèle, contrôleur, service, seed ni test existant n'a été modifié.

- Création : `backend/db/oracle/001_schema.sql`
- Suppression : `backend/db/oracle/000_drop.sql` (ordre inverse des dépendances)
- Application : `backend/src/scripts/oracle-schema.js`
  - `npm run db:oracle:schema` (racine) ou `npm run oracle:schema --prefix backend`
  - `--drop` supprime (ORA-00942 « table absente » ignoré), `--reset` supprime puis crée
  - `--drop`/`--reset` refusés si `NODE_ENV=production`
  - sortie : `Schéma Oracle créé : 27 objets` ou `Échec Oracle : <message>` (exit 1)
  - le SQL n'est jamais lié (`knex.raw` sans `?`), une instruction à la fois

## Règles appliquées

| Règle | Application |
| --- | --- |
| Noms | MAJUSCULES sans accents, `snake_case`, sans guillemets, aucun mot réservé Oracle (`DATE`, `END`, `START`, `TYPE`, `VALUES`, `STATUS`, `OBJECT`, `TEXT`, `VERSION`, `KIND` évités : `DATE_DEBUT`, `TYPE_REF`, `STATUT`, `OBJET`, `TEXTE`, `VERSION_MODULE`, `GENRE`) |
| Clé primaire | `ID NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` (`BY DEFAULT` : les seeds pourront imposer des id) ; exception : les tables de jonction `MODULE_PERIODICITE` et `MODULE_TYPE_STRUCTURE` ont une PK composite |
| Chaînes | `VARCHAR2(n CHAR)` (longueur en caractères, pas en octets) |
| Booléens | `NUMBER(1) DEFAULT x NOT NULL` + `CHECK (col IN (0,1))` |
| Énumérations | `VARCHAR2` + `CHECK (col IN (...))` avec exactement les valeurs des modèles ; la largeur = la valeur la plus longue |
| Dates | `TIMESTAMP(3) WITH TIME ZONE` |
| Horodatage | `CREATED_AT` et `UPDATED_AT` sur **chaque** table (`NOT NULL DEFAULT SYSTIMESTAMP`) ; `JOURNAL_AUDIT` n'a que `CREATED_AT` ; **aucun trigger** (l'application renseignera `UPDATED_AT`) |
| Chaîne vide | `''` vaut `NULL` en Oracle : `REFERENTIEL.MINISTERE/REGIME/ACRONYME` sont `NULLABLE`, sans `DEFAULT ''` |
| Contraintes nommées | `PK_<t>`, `FK_<t>_<c>`, `UQ_<t>_<c>`, `CK_<t>_<c>`, `IX_<t>_<c>` |
| Index FK | chaque colonne de clé étrangère est indexée (`PK_` composite menant la colonne suffit) |
| ON DELETE CASCADE | uniquement sur les tables enfants : `MODULE_PERIODICITE`, `MODULE_TYPE_STRUCTURE`, `SAISIE_VALIDATION` |
| Longueurs | valeurs de l'énoncé ; `REMARQUE.TEXTE = 2000` (zod `max(2000)`), `JOURNAL_AUDIT.OBJET = 200` (usage : `saisie:<id>`, `utilisateur:<id>`, `login`) |
| CLOB | inutilisé : la plus longue colonne `VARCHAR2` fait 2000 caractères (< 4000) |
| JSON | type natif `JSON` Oracle 21c : `MODULE_SIGBD.FIELDS_JSON`, `SAISIE.VALEURS_JSON` |

| `dates.exported` | `DATE_EXPORT` | `TIMESTAMP(3) WITH TIME ZONE` | nullable |
| index unique partiel `{structureId, moduleId, periodeId}` | index unique fonctionnel `UQ_SAISIE_PERIODE` | `CREATE UNIQUE INDEX UQ_SAISIE_PERIODE ON SAISIE (CASE WHEN PERIODE_ID IS NOT NULL THEN STRUCTURE_ID END, CASE WHEN PERIODE_ID IS NOT NULL THEN MODULE_ID END, PERIODE_ID)` | voir ci-dessous |
| `createdAt` / `updatedAt` | `CREATED_AT` / `UPDATED_AT` | `TIMESTAMP(3) WITH TIME ZONE` | `NOT NULL DEFAULT SYSTIMESTAMP` |

**Pourquoi un index fonctionnel :** Oracle traite `(x, y, NULL)` comme un doublon, ce
qui bloquerait les modules d'événement (`PERIODE_ID NULL`). Les `CASE` renvoient
`NULL` pour une saisie d'événement : ces lignes ne sont jamais en conflit, alors que
deux saisies périodiques identiques (structure, module, période) sont refusées
(ORA-00001).
